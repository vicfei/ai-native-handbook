# Publishing rules

- **Openness ruling (owner decision):** technical detail is fully open — real parameters, real topologies, real incident timelines may all be published. The only exclusions: **company names and company domains never appear; credentials (API keys, passwords, tokens, private keys) never enter a public repo.** The credential line is operational security, not secrecy preference: a published credential is a compromised credential, and adds nothing to a handbook.
- In chapter text, use placeholders (`sk-xxx`) plus a note on where to obtain the real value (e.g. "platform console → API Keys").
- When referencing internal ledgers or tickets, port conclusions and numbers only — not links.

（中文对照：技术细节完全开放——真实参数、真实拓扑、真实事故时间线均可入库；唯一排除项：公司名与公司域名不出现；凭据（key/密码/token/私钥）任何情况下不入公开仓——凭据线是运维安全而非保密偏好：公开即泄露，且对手册零贡献。正文用占位符并注明获取途径；引用内部台账只搬结论与数字，不搬链接。）
