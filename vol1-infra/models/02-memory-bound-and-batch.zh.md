# 02 · 访存受限、Roofline 与批量的数学本质

> 一句话地基：**生成每一个 token，GPU 都要把全部模型权重从显存完整读一遍。** 本章推导它为什么成立、贵在哪、以及所有主流优化各自攻它的哪一项。

## 快递站模型（一张图记住全局）

- **显存** = 仓库货架（数字躺在这里）；**计算单元** = 操作台上的工人；两者之间靠**搬运通道**（显存带宽）。
- **每跑一次前向 = 送一趟货必须清点整个仓库**（全部权重各用一次）→ 固定装车成本。
- **批量（batch）= 拼车**：一趟车捎 96 个包裹，装车成本被摊薄 96 倍。

## 两条必然性（铁律的构成）

1. **结构必然**（函数复合）：层层数学串联（见 [01 章](01-from-transformer-to-token.md)），每次前向必须穿过每张表；
2. **物理必然**（冯·诺依曼架构）：数字在显存、运算在计算单元，**数字不动、运算不动手**——要算它就必须先搬它。工人手边的寄存器只有 KB~MB 级，54GB 塞不进去。

## 算账：工人到底有多闲（27B 模型、生成 1 个 token）

```
搬运成本：54 GB ÷ 4 TB/s（H20 显存带宽）   ≈ 13.5 ms   ← 每 token 的地板时间
计算成本：~54 GFLOP ÷ 148 TFLOPS（H20）     ≈ 0.37 ms
工人利用率 ≈ 0.37 / 13.5 ≈ 3%
```

这就是**访存受限（memory-bound）**的定量含义：瓶颈是搬运，不是干活。

## Roofline：判断瓶颈的第一工具

**算术强度** = 计算量 ÷ 搬运量（FLOP/字节）。每个权重数字"搬 2 字节、算 2 次"（乘+加），所以单请求生成强度恒为 **1 FLOP/B**。

硬件的**平衡点** = 算力 ÷ 带宽 = 148 ÷ 4 = **37 FLOP/B**：

- 强度 < 37 → 料等工（访存受限）
- 强度 > 37 → 工等料（算力受限）

**批量的数学本质**：batch=96 时每个权重数字仍只搬一次，却被乘 96 次 → 强度 ×96 = 96 > 37 → **瓶颈翻转**。拼车没有少搬一件货，只是让每件货干了 96 份活。

## 优化工具箱：每一项攻铁律的哪一项

| 技术 | 通俗本质 | 攻的是 |
|---|---|---|
| **批量（continuous batching）** | 一趟车捎多个包裹，装车成本摊薄 | 结构必然的成本摊销 |
| **量化（fp8/int8/int4）** | 每件货体积缩小 → 搬运量同比下降 | 物理必然的搬运量 |
| **MoE（混合专家）** | 仓库分区，每个 token 只逛需要的几区 | 结构必然的"每表必读" |
| **MTP/投机解码** | 一趟车顺路带回 3 个字核对，少跑两趟 | 串行循环的固定成本次数 |
| **KV cache** | 历史笔记不重算（省的是激活重算，不省权重读取） | 前处理冗余 |

## 延伸：MTP 为什么低并发赚、高并发亏

MTP 的收支结构：**省带宽（少跑几趟车），花算力（草稿要生成、要校对，被拒的草稿是白搬的箱子）**。

| | 低并发（车少人闲） | 高并发（车满人忙） |
|---|---|---|
| 省的（带宽） | 正中要害 ✅ | 无关痛痒（瓶颈已不是车） |
| 花的（算力） | 工人闲着，白搬免费 ✅ | 挤占真包裹的工人 ❌ |
| 净效果 | 大赚 | 可能倒贴 |

**配置启示**：`max-num-seqs`（并发定位）与投机解码参数（低批量最优）写在同一份配置里时，说明两种服务形态被混在一起——正确做法是测"接受率 × 并发"曲线后分档（低载开投机、饱和关或降），或用引擎的 adaptive verification 让它实时决定。
